# Спортивные челленджи — Telegram-бот + Web App

Telegram-бот с Web App для трекинга ежедневных спортивных челленджей. Первый челлендж —
**«Планка каждый день»**: участники ежедневно присылают видео-кружок с планкой в общий чат,
бот отслеживает выполнение, серии, болезни, штрафы и общий банк, а каждое утро шлёт отчёт
за предыдущий день с мотивационной речью.

## Возможности

- **Подтверждение планки** — бот ловит видео-кружки в общем чате, засчитывает при длительности
  ≥ минимума (по умолчанию 60 сек) и до дедлайна (23:59).
- **Модерация** — под каждым засчитанным кружком админ может нажать «Фейк (×2)» или
  «Не засчитывать»; штрафы пересчитываются автоматически.
- **Болезни** — команда `/sick` или кнопка в боте до 14:00 освобождает от штрафа за день.
- **Заморозка серии** — за каждые 30 дней подряд участник получает заморозку (максимум 3 на руках,
  оба числа меняются в админке). Тратит её сам в кабинете и только на пропущенный день не раньше
  дня, когда она заработана: серия не рвётся, штраф за пропуск остаётся.
- **Дневной отчёт** — каждое утро в чат: кто сделал/пропустил/болел, день челленджа, серии,
  банк и одна из ~40 редактируемых мотивационных речей.
- **Напоминания** — вечером тем, кто ещё не прислал кружок. Каждый участник может задать
  своё время (шаг 30 минут) или отключить личные напоминания в кабинете.
- **Взвешивание** — отдельный челлендж-группа без кружков, дедлайнов и штрафов: у каждого
  участника своя история веса, динамика за неделю/месяц, график и состав тела. Данные
  прилетают с Bluetooth-весов через Android-приложение openScale (см. раздел «Умные весы»),
  о свежем взвешивании бот пишет в ЛС. Цифры личные — другие видят только имя. Если на весы
  встаёт вся семья с одного телефона, взвешивания раскладываются по участникам через профили
  openScale.
- **Банк** — учётный реестр (штрафы пополняют, траты списывают); сумму можно править вручную.
- **Web App** — профиль (серия, рекорд, пропуски, штрафы, статус), заморозки серии (сколько
  доступно/использовано + история), личные уведомления, рейтинг, правила.
- **Админка** (внутри Web App, для пользователей с правами) — редактирование всех настроек:
  штраф, множитель за фейк, дедлайны, минимум планки, параметры заморозки серии, текст правил,
  даты, чат, банк, речи, участники, лента последних событий участников с ручными правками
  статусов, запуск отчёта.

## Стек

- **Сервер:** Node.js + TypeScript, [grammY](https://grammy.dev) (бот), [Fastify](https://fastify.dev) (API), [Prisma](https://www.prisma.io) + PostgreSQL, node-cron.
- **Фронт:** Vue 3 + Vite (Telegram Web App).
- **Деплой:** Docker Compose (app + Postgres + Caddy с авто-HTTPS).

## Настройка бота в Telegram (@BotFather)

1. Создайте бота: `/newbot`, получите **BOT_TOKEN**.
2. **Отключите privacy mode** (иначе бот не увидит чужие кружки в группе):
   `/setprivacy` → выберите бота → **Disable**.
   *Либо* сделайте бота **администратором** общей группы — тогда он получает все сообщения
   независимо от privacy mode.
3. Привяжите Web App: `/newapp` (или `/setmenubutton`) и укажите URL `https://<ваш-домен>`.
4. Узнайте свой Telegram ID (напишите [@userinfobot](https://t.me/userinfobot)) и впишите его
   в `ADMIN_TELEGRAM_IDS`.

## Деплой на VPS (Docker)

Требуется: домен, указывающий A-записью на IP сервера, и установленный Docker + Docker Compose.

```bash
cp .env.example .env
# заполните BOT_TOKEN, PUBLIC_DOMAIN, WEBAPP_URL, WEBHOOK_SECRET, ADMIN_TELEGRAM_IDS, POSTGRES_PASSWORD
docker compose up -d --build
```

При старте контейнер `app`:
- применяет схему к БД (`prisma db push`),
- сидирует челлендж «Планка» и ~40 речей (идемпотентно),
- запускает сервер (бот + API + cron) и устанавливает webhook.

Caddy сам получит TLS-сертификат Let's Encrypt для `PUBLIC_DOMAIN`.

После запуска:
1. Добавьте бота в общую группу (админом либо с отключённым privacy mode).
2. В группе выполните `/bindchat` (от админа) — чат привяжется к челленджу, кружки начнут
   засчитываться. Узнать id чата можно командой `/chatid`.
3. Откройте Web App у бота и нажмите «Участвовать» в карточке челленджа — участие явное,
   само оно не появляется. Там же профиль и (для админов) раздел «Админ».

## Локальная разработка

Нужны Node.js 20+ и PostgreSQL (можно поднять только БД: `docker compose up -d db`).

```bash
# сервер
cd server
cp ../.env.example .env        # DATABASE_URL → ваш локальный/докерный Postgres
#   для localhost: postgresql://challenge:challenge@localhost:5432/challenge
#   USE_WEBHOOK=false (long polling, не нужен публичный URL для самого бота)
npm install
npm run prisma:generate
npm run prisma:migrate:dev      # или: npx prisma db push
npm run prisma:seed
npm run dev                     # бот (long polling) + API на :3000

# фронт (в другом терминале)
cd web
npm install
npm run dev                     # Vite на :5173, /api проксируется на :3000
```

Для проверки Web App в браузере без Telegram задайте `web/.env`:
```
VITE_DEV_TELEGRAM_ID=<ваш_telegram_id>
```
— сервер в dev-режиме (`NODE_ENV != production`) примет этот заголовок вместо initData.

Сам Web App внутри Telegram требует HTTPS — для тестирования поднимите туннель
(`cloudflared tunnel --url http://localhost:5173` или `ngrok http 5173`) и укажите его URL в
`WEBAPP_URL` и в кнопке Web App у @BotFather.

### Быстрый smoke-тест API (без бота)

Проверяет весь путь API → сервисы → БД на запущенном Postgres с применённой схемой и сидом:

```bash
cd server
# поднимите БД (docker compose up -d db) и примените схему: npx prisma db push && npm run prisma:seed
DATABASE_URL=postgresql://challenge:challenge@localhost:5432/challenge \
  ADMIN_TELEGRAM_IDS=999 NODE_ENV=development npm run smoke
```

Скрипт дёргает `/api/challenge`, `/api/me`, `/api/leaderboard`, админские роуты (банк, речи,
участники, ручная правка дня, запуск отчёта) под dev-пользователем `999` и печатает результаты.

Пересчёт заморозок серии по всем участникам (сколько заработано / потрачено / доступно):

```bash
cd server
DATABASE_URL=postgresql://challenge:challenge@localhost:5432/challenge npm run freezes
```

## Типы челленджей

У челленджа есть `kind`:

| kind | Что это | Механика |
|---|---|---|
| `plank` | «Планка каждый день» | кружки, дедлайны, больничные, серии, заморозки, штрафы, банк, отчёты |
| `weight` | «Взвешивание» | ничего из перечисленного: только состав участников и личный вес у каждого |

Механика планки живёт вокруг `getActiveChallenge()`, а она возвращает только `kind = 'plank'`:
бот, планировщик, админка и автоматическое зачисление новых пользователей группу взвешиваний
не видят. Планочные роуты (`/me`, `/leaderboard`, `/sick`, `/freezes`, `/notifications`) для
весового челленджа отвечают `400 not_applicable`.

Участие в любом челлендже — явное. Ни `/start`, ни открытие приложения в челлендж не
записывают: человек видит его в списке под заголовком «Ещё доступно» и жмёт «Участвовать»
(`POST /api/challenges/:id/join`). Так зашедший ради весов не оказывается в планке со
штрафами за пропуски. Из группы взвешиваний можно выйти там же (`/leave`) — история веса
остаётся; из планки участника убирает админ.

Группа заводится сидом (`key: weight`), как и планка.

## Как считается планка

- Кружок (`video_note`) от зарегистрированного участника в привязанном чате с
  `duration ≥ minDurationSec` → засчитан (`counted`). После дедлайна → `late` (= пропуск, штраф).
- Содержание (реально ли планка, не монтаж) автоматически не проверяется — для этого ручная
  модерация админом: «Фейк (×2)» (двойной штраф) или «Не засчитывать».
- Нет ни кружка, ни валидного больничного к концу дня → пропуск, штраф `fineAmount`.
- Серия (`streak`) — последовательные дни с засчитанной планкой; валидный больничный её
  «замораживает» (настраивается `freezeStreakOnSick`).
- Заморозка серии (`StreakFreeze`) — участник тратит её в кабинете на пропущенный день: день
  серию не рвёт и не наращивает (как больничный), штраф за пропуск остаётся. Заработанные
  заморозки нигде не хранятся, а всегда считаются из истории: каждые `freezeEveryDays` дней
  подряд — одна, на руках не больше `maxFreezes` (0 в любом из полей выключает фичу). Поэтому
  у всех участников, включая накопивших серию раньше, заморозки посчитались сами. Посмотреть
  расклад по всем: `npm run freezes` в `server/`. Применить заморозку можно только на день не
  раньше того, за который она получена; ручная правка дня админом (кроме «пропуска») снимает
  заморозку и возвращает её участнику.

## Умные весы (Mi Body Composition Scale 2 и другие BLE-весы)

Весы не умеют в интернет — результат они отдают по Bluetooth. Цепочка такая:

```
весы --BLE--> openScale (Android) --> openScale sync --webhook--> POST /api/ingest/openscale
```

Что нужно на телефоне (оба приложения с открытым кодом, есть в F-Droid):

1. [openScale](https://github.com/oliexdev/openScale) — снимает данные с весов. Заведите
   пользователя (пол, рост, возраст: без них не посчитается состав тела) и добавьте весы.
2. [openScale sync](https://github.com/oliexdev/openScale-sync) — пересылает измерения наружу.
   Включите **Webhook**, вставьте адрес и заголовок из кабинета: челлендж «Взвешивание» →
   «Подключение весов». Кнопка проверки связи в приложении должна дать зелёный ответ.

Дальше всё само: встали на весы с телефоном рядом — измерение появилось в кабинете, бот написал
в ЛС вес и разницу с прошлым разом. При первом подключении openScale выгружает всю накопленную
историю; о такой пачке бот молчит, чтобы не завалить личку.

### Несколько человек на одних весах

**У каждого свой телефон.** Ничего настраивать не нужно: токен личный, каждый берёт свой в
кабинете. Весы копят измерения во внутренней памяти и отдают их телефону при подключении, так
что взвешиваться можно по очереди.

**Один телефон на всех.** Заведите в openScale по пользователю на человека и включите умное
назначение: приложение сравнивает новый вес с последним весом каждого профиля и отдаёт
измерение ближайшему (допуск в процентах настраивается, измерения вне допуска можно
отбрасывать). В вебхук такие измерения уходят с разными `userId` и `username`.

Токен при этом привязан к телефону, а не к человеку на весах, поэтому раскладывает измерения
сервер. Каждый новый профиль openScale заводится автоматически (`ScaleProfile`) и до
назначения пишет владельцу телефона. Когда профилей больше одного, в кабинете владельца
появляется карточка **«Кто на весах»**: напротив каждого профиля выбирается получатель
(из участников группы «Взвешивание») —
и вместе с профилем к нему переезжает уже накопленная история.

Отдать профиль можно только участнику той же группы взвешиваний. Если у получателя уже есть
взвешивание с тем же временем, такая запись остаётся на месте — ответ вернёт, сколько записей
переехало (`moved`) и сколько пропущено (`skipped`).

### Контракт эндпоинта

`POST /api/ingest/openscale`, авторизация — личный токен пользователя в заголовке
`Authorization: Bearer <token>` (принимается и голый токен, и `X-Scale-Token`, и `?token=`).
Токен выдаётся в кабинете, там же перевыпускается. Telegram initData здесь ни при чём: запрос
идёт с телефона, поэтому роут вынесен из `userRoutes` в `ingestRoutes`.

Обрабатываются события openScale sync:

| Событие | Что делает сервер |
|---|---|
| `test` | отвечает 200 (кнопка проверки связи в приложении) |
| `insert` / `update` | сохраняет измерение; повтор того же взвешивания не плодит дублей |
| `delete` | удаляет взвешивание за это время |
| `clear` | **игнорирует** — стирать историю по внешней команде слишком опасно |

Вес приходит в килограммах, жир/вода/мышцы — в процентах (нули = «не измерено»). Состав тела
считает само приложение по сопротивлению тела, цифры ориентировочные — смотреть стоит на тренд.

Проверить руками:

```bash
curl -X POST "https://<домен>/api/ingest/openscale" -H "Authorization: Bearer <token>" -H "Content-Type: application/json" -d '{"event":"insert","id":1,"userId":1,"date":"2026-09-21T07:14:33.120Z","weight":78.4}'
```

## Команды бота

| Команда | Доступ | Назначение |
|---|---|---|
| `/start` | все | регистрация + кнопка Web App |
| `/app` | все | кнопка запуска Web App (работает и в группе) |
| `/sick` | участники | сообщить о болезни на сегодня |
| `/rules` | все | правила челленджа |
| `/id` | все | узнать свой Telegram ID |
| `/chatid` | админ | id текущего чата |
| `/bindchat` | админ | привязать текущий чат к челленджу |
| `/pinapp` | админ | опубликовать и закрепить кнопку запуска приложения |
| `/report [YYYY-MM-DD]` | админ | вручную сформировать и отправить отчёт |

## Открытие Web App из группы

Inline-кнопки `web_app` Telegram разрешает только в личке. Чтобы запускать приложение из
группы, используется **Direct Link Mini App**: настройте в @BotFather **Main Mini App** (или
`/newapp` с коротким именем) с URL вашего домена. После этого работают `/app`, `/pinapp` и
кнопки в отчётах. `/pinapp` публикует и закрепляет кнопку запуска вверху группы.

## Авто-деплой

Деплой по пушу в `main` через **GitHub Actions на self-hosted раннере**
(`.github/workflows/deploy.yml`). Раннер развёрнут прямо на сервере, поэтому деплой выполняется
локально (без SSH) и не зависит от GitHub-hosted минут/биллинга. Шаги job:
`git fetch && git reset --hard origin/main && docker compose up -d --build`.

Сервер развёрнут как git-клон в `/opt/challenge`; `.env` лежит рядом (в `.gitignore`) и
`git reset --hard` его не трогает. Раннер: служба
`actions.runner.Fedos16-plank-challenge-bot.challenge-vps` (`/opt/actions-runner`, под root).
